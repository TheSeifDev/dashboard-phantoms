# Web Projects API / Database Contract

**Contract status:** Stable for the backend migration currently being implemented. This is a database contract, not a claim that the migration has been applied. The migration remains local and pending. All UUID project identifiers are separate from Internal Teams; all people references use the existing `public.members.id` bigint identity. Authenticated member actions resolve through the existing `member_auth_bindings`; clients must not submit an actor/member identity as proof of authorization.

## Authorization and visibility

The feature permission is the new boolean `admin_accounts.permissions.web_projects`. It is false for existing admins after migration backfill. A system Owner has implicit program-admin access; an admin needs the explicit bit. This permission grants no Team authority. Project roles are `lead`, `contributor`, and `viewer`, scoped to one project. A member's project membership is pending until accepting the current versioned agreement; only active members whose accepted version matches the project version get ordinary workspace access.

RLS is the authority for direct table access. Program admins can access the Web Projects program. Active agreement-accepted project members can read that project's ordinary workspace records. Leads/program admins manage scoped project configuration. Contributors can create their own updates, deliverables, comments, attachments and reports as allowed by each table; task status moves must use the transition RPC. Viewers are read-only. A pending invitee can read their own membership and the current agreement to accept it, but not general project work. Report content is visible only to its author, that project's lead, and program admins. Shared resources are visible only when approved; project-scoped resources are visible only in that project. Append-only activity is project-scoped and contains metadata, never report text.

All child relationships carry `project_id` and use composite foreign keys for same-project task, milestone, sprint, membership, and resource references. Project, milestone, and sprint progress are derived from persisted work rows; no user-supplied completion percentage is stored. `web_project_progress`, `web_project_milestone_progress`, and `web_project_sprint_progress` expose derived counts and nullable percentages (null means there is no tracked work).

All tables below are in `public` and use the `web_` namespace. UUID primary keys are generated by the database unless noted. Read queries should include the relevant `project_id` filter; RLS enforces the security boundary independently.

## RPCs

Call via authenticated Supabase RPC. All privileged functions use fixed empty `search_path`; authorization is derived from `auth.uid()`, the canonical member binding, and stored project membership. Errors are raised for unauthorized, stale, or invalid transitions.

| RPC | Parameters | Return |
|---|---|---|
| `web_set_program_admin_access` | `p_user_id uuid`, `p_enabled boolean` | `boolean`; Owner-only explicit grant/revoke of the separate `web_projects` admin bit, with audit. |
| `web_list_member_candidates` | `p_project_id uuid DEFAULT NULL` | Rows `(member_id bigint, full_name text)` only. A null project requires program-admin access; with a project ID, an accepted lead or program admin can list eligible active canonical members not already participating. No contacts or profile extras are returned. |
| `web_list_project_roster` | `p_project_id uuid` | Rows `(project_id uuid, member_id bigint, role text, status text, responsibility text, accepted_agreement_version integer, agreement_accepted_at timestamptz, added_by_auth_user_id uuid, created_at timestamptz, updated_at timestamptz, full_name text)`; project-scoped, no contact details. |
| `web_list_my_project_invitations` | none | Rows `(project_id uuid, project_name text, role text, status text, current_agreement_version integer, ownership_model text, ownership_notes text, license_name text, attribution_notes text, terms jsonb)` for the authenticated caller's own pending membership only. |
| `web_create_idea` | `p_details jsonb`, `p_contributor_member_ids bigint[] DEFAULT '{}'` | `uuid` idea ID; a bound member can submit only as themselves, while a program admin can select an existing bound submitter; contributor IDs are candidate metadata, not authorization. |
| `web_review_idea` | `p_idea_id uuid`, `p_decision text`, `p_notes text DEFAULT ''` | `text` review status; program-admin-only `under_review`, `approved`, or `rejected` transition. |
| `web_create_project` | `p_name text`, `p_slug text`, `p_owner_member_id bigint`, `p_lead_member_id bigint DEFAULT NULL` | `uuid` project ID; program-admin-only, creates agreement version 1 and pending memberships. |
| `web_convert_idea_to_project` | `p_idea_id uuid`, `p_project_slug text`, `p_lead_member_id bigint DEFAULT NULL` | `uuid` project ID; approval required; transaction-safe and idempotent; returns the same project on repeated conversion. |
| `web_add_project_member` | `p_project_id uuid`, `p_member_id bigint`, `p_role text`, `p_responsibility text DEFAULT ''` | `text` membership status; only program admins/project leads; roles are contributor/viewer (lead assignment uses the dedicated RPC); new/changed participation is pending agreement acceptance. |
| `web_set_project_member_status` | `p_project_id uuid`, `p_member_id bigint`, `p_status text` | `text`; authorized project lead/program admin can set only `suspended` or `removed`; no Auth identity or other-project membership is changed. |
| `web_set_project_leader` | `p_project_id uuid`, `p_member_id bigint` | `boolean`; authorized lead/admin only, handoff requires new leader acceptance. |
| `web_accept_project_agreement` | `p_project_id uuid`, `p_version integer` | `boolean`; current member may accept only their own current pending membership/current version; idempotent. |
| `web_amend_project_agreement` | `p_project_id uuid`, `p_ownership_model text`, `p_ownership_notes text`, `p_license_name text`, `p_attribution_notes text`, `p_terms jsonb DEFAULT '{}'` | `integer` new version; records an immutable snapshot and returns members to pending until they accept. Branding/showcase are reset off. |
| `web_record_project_consent` | `p_project_id uuid`, `p_consent_type text`, `p_granted boolean` | `uuid` consent event; a member may record only their own explicit consent for the current version. Revocation disables the related project permission. |
| `web_set_project_permissions` | `p_project_id uuid`, `p_brand_use boolean`, `p_public_showcase boolean` | `boolean`; program admin/lead only; enabling requires current explicit consent from every active lead/contributor. |
| `web_set_project_status` | `p_project_id uuid`, `p_status text` | `boolean`; program admin/lead only; activating requires an accepted current lead. |
| `web_transition_project_task` | `p_task_id uuid`, `p_to_status text`, `p_comment text DEFAULT NULL` | `text` resulting status; project lead/admin or an assigned contributor may make a legal workflow transition. |
| `web_delete_project_task` | `p_task_id uuid` | `text` status `cancelled`; authorized lead/program admin soft-cancels the task, preserving comments, assignments, attachments, and audit history. Physical task deletion is not exposed. |
| `web_submit_member_report` | `p_project_id uuid`, `p_period_start date`, `p_period_end date`, `p_completed_this_week text`, `p_working_on text`, `p_next_week_plan text`, `p_deliverables_complete boolean`, `p_blockers text`, `p_support_needed boolean`, `p_references_and_attachments jsonb DEFAULT '[]'` | `uuid` report ID; canonical author only; creates or revises that author's open weekly report. |
| `web_review_member_report` | `p_report_id uuid`, `p_status text`, `p_review_notes text`, `p_blocker_escalated boolean DEFAULT false` | `text` report status; project lead/program admin only. |

Task/project work that does not have a dedicated RPC uses ordinary table operations protected by RLS and same-project FKs. Leads can edit task parent/milestone/sprint assignments only within the same project; assigned contributors cannot change those links. Project membership/agreement/consent/review state is RPC-only. Direct `web_project_tasks.status` updates are not granted; use the transition RPC. Task “delete” is a visible soft cancel via `web_delete_project_task`, never a physical delete.

## Progress queries

Select the views with the corresponding `project_id`:

- `web_project_progress`: `project_id`, `task_count`, `completed_task_count`, `progress_percent` (nullable; cancelled tasks excluded from the denominator).
- `web_project_milestone_progress`: `project_id`, `milestone_id`, `milestone_title`, `linked_task_count`, `completed_task_count`, `linked_deliverable_count`, `accepted_deliverable_count`, `tracked_item_count`, `completed_item_count`, `progress_percent` (nullable).
- `web_project_sprint_progress`: `project_id`, `sprint_id`, `sprint_name`, `task_count`, `completed_task_count`, `blocked_task_count`, `progress_percent` (nullable).

No report text, project private information, or unrelated project's work is made available through these views outside the same RLS access boundary.
